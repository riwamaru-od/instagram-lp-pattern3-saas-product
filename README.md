## 1. 参考LPから何を受け継いだか

dfplus.io のLPは、**プロダクトを検討する人が知りたい順番**に並んでいます。
感情に訴えるのではなく、できること・解決すること・導入コストを淡々と積み上げる構造です。

| 参考LPの特徴 | このお手本での再現 |
| --- | --- |
| メインカラー #28AFA0（ティール）＋ #FEA400（オレンジ） | 同じ配色を採用（※後述の理由で文字用は濃度を調整） |
| 背景の淡いグレー #F5F8FA で章を区切る | `.section--tint` として同じ手法 |
| 「〜でもう悩まない」という言い切りのヘッドコピー | 「Instagram運用のことで、もう悩まない。」 |
| 「必要な機能がオールインワン」で価値を1行に | 「運用に必要なスキルがオールインワン」 |
| お悩み（h3）→ 解決（h4）をペアで見せる | PROBLEM セクションで同じ構造を実装 |
| 導入事例を3枚のカードで見せる | CASE セクション（業種タグ＋成果数値） |
| 料金プランと「最短◯時間で完了」 | PRICE と「最短2週間で開始できます」 |
| ヘッダーに2種類のCTA（資料／相談） | 同じく2種類を配置 |

### SaaS型LPの型
```
「何ができるか」を1行 → 機能3本柱 → 悩み→解決 → 選ばれる理由
→ 導入事例 → 料金 → 導入の流れ → FAQ → CTA
```
この順番は、検討者が社内稟議を通すために必要な情報の順番でもあります。

## 3. ⚠️ 最重要ポイント：ブランドカラーと可読性

**このお手本でいちばん学んでほしいのはここです。**

参考LPのメインカラー `#28AFA0` は美しい色ですが、
そのまま白文字を載せると**コントラスト比は約 2.7:1** にしかなりません。
WCAG 2.1 のAA基準は、通常サイズの文字で **4.5:1**、大きい文字で **3:1** です。つまり不合格です。

### 解決策：トークンを「塗り用」と「文字用」に分ける

```css
:root{
  --c-brand:       #28AFA0;  /* 塗り・グラフ・アイコン用（見た目の印象を担う） */
  --c-brand-dark:  #0F7A6E;  /* 文字・ボタン背景用（白文字で 5.2:1） */
  --c-accent:      #FEA400;  /* 塗り専用のオレンジ */
  --c-accent-text: #A06000;  /* 文字用のオレンジ（白背景で 5.1:1） */
}
```

ブランドの見え方は `--c-brand` が担い、読みやすさは `--c-brand-dark` が担います。
**ブランドカラーを守ることと、読めることは両立できます。**

### グラデーションの落とし穴
```css
/* NG：終点が明るすぎて、白文字が 2.7:1 になる */
background: linear-gradient(120deg, #123B3E, #15887B, #28AFA0);

/* OK：いちばん明るい終点でも白文字が 5.2:1 */
background: linear-gradient(120deg, #123B3E, #0B5F55, #0F7A6E);
```
グラデーションの上に文字を置くときは、**いちばん明るい地点**で判定してください。

### 確認方法
- Chrome DevTools の色ピッカーにコントラスト比が表示されます
- Lighthouse の Accessibility 監査
- WebAIM Contrast Checker

## 5. 実装で押さえたポイント

### 5-1. 悩み → 解決を1枚のカードにまとめる
```html
<article class="problem">
  <div class="problem__q">  <p>お悩み 01</p> <h3>…</h3> </div>
  <div class="problem__a">  <p>解決</p>      <h4>…</h4><p>…</p> </div>
</article>
```
悩みと解決が離れていると、読み手が対応関係を探す手間が生まれます。
CSSの `::before` で三角形を描き、視覚的にも「落ちる」動きを表現しています。

### 5-2. FAQPage 構造化データ
```json
{ "@context": "https://schema.org", "@type": "FAQPage", "mainEntity": [ … ] }
```
検索結果に質問と回答が展開表示されることがあります（リッチリザルト）。
**ページ内に実際に表示されている内容と一致させること**が条件です。
表示していないFAQを構造化データにだけ書くのは規約違反になります。

### 5-3. プロダクトUIをCSSで表現する
ヒーローのダッシュボードは画像ではなくCSSです。
SaaS型LPでは「画面の雰囲気」を見せたいだけの場合が多く、
CSSで作れば軽く、文言の差し替えもコードで完結します。
なお装飾なので、コンテナに `aria-hidden="true"` を付けています。

### 5-4. ハンバーガーメニューは状態を同期させる
```js
const isOpen = gnav.classList.toggle('is-open');
navToggle.setAttribute('aria-expanded', String(isOpen));
```
見た目だけ変えて `aria-expanded` を更新しないのはよくある誤りです。
スクリーンリーダー利用者には「開いているかどうか」が伝わりません。

### 5-5. `grid-template-rows: 0fr → 1fr` で高さアニメーション
```css
.gnav{ display: grid; grid-template-rows: 0fr; transition: grid-template-rows .3s; }
.gnav.is-open{ grid-template-rows: 1fr; }
.gnav__list{ overflow: hidden; }
```
`height: auto` はアニメーションできません。
JSで高さを計算する方法もありますが、この書き方ならCSSだけで完結します。

### 5-6. 2種類のCTAの使い分け
- 主CTA（塗り）… 無料相談＝いますぐ動ける人向け
- 副CTA（線）… 資料請求＝社内で検討したい人向け

**視覚的な強さを必ず変えます。** 同じ強さで2つ並べると、どちらも押されません。
